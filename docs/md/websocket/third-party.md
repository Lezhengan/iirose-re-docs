# 第三方开发指南（机器人 & 客户端）

> 本章是**所有第三方开发者**的入口文档，覆盖**机器人**（自动收发消息）和**自定义客户端**（替代官方 UI）两大场景。内容来自官方前端 `messages.js` 与 koishi adapter-iirose（`src/utils/ws/*`、`src/encoder/*`、`src/decoder/*`）的交叉比对，已用一套可运行实现验证。与官方网页端的差异会单独标注。

## 整体架构：WS + HTTP 双通道

蔷薇花园的通信模型是「**WS 承载房间内实时交互 + HTTP 承载辅助服务**」，第三方开发需要同时理解两者：

```text
┌─ 第三方客户端 / 机器人 ──────────────────────────────────┐
│                                                          │
│  ┌─ WS（wss://m{N}.iirose.com:8778）──────────────────┐  │
│  │  • 进房认证（* + JSON）                            │  │
│  │  • 聊天 / 私聊 / 广播 / 弹幕                        │  │
│  │  • 股票 / 银行 / 商店 / 论坛 / 任务 / 朋友圈         │  │
│  │  • 点歌 / 点播 / 媒体管理                           │  │
│  │  • 关注 / 点赞 / 打分 / 转账                        │  │
│  │  • 房主管理 / 踢人 / 禁言                           │  │
│  │  • 用户资料 / 排行榜 / 房间列表                      │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  ┌─ HTTP ────────────────────────────────────────────┐  │
│  │  • 登录（限流检查）                                 │  │
│  │  • 媒体解析（网易云/QQ/B站等）                     │  │
│  │  • 翻译                                          │  │
│  │  • 支付                                            │  │
│  │  • 文件/图片上传                                     │  │
│  │  • 用户名搜索  → 见 发送命令                       │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  ┌─ 静态资源 ────────────────────────────────────────┐  │
│  │  • 头像                                            │  │
│  │  • 上传回显                                         │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

## 核心结论

1. **房间内主要业务命令走 WS**：聊天、私聊、广播、切房、进房认证、股票、银行、商店、论坛、任务、朋友圈、排行榜、点歌、点播、关注/点赞/打分/转账、房主管理、媒体管理——这些功能的主要控制消息使用 WS，但资源获取与具体操作还可能涉及 HTTP。但媒体解析（网易云/QQ音乐/B站等链接解析）、翻译、支付、图片/文件上传等辅助功能存在 HTTP 路径；用户名搜索另有 WS `=-+`，不能按“辅助功能”统一归入 HTTP（详见[发送命令](md/websocket/commands.md)）。
2. **实际可用地址**：`wss://m{N}.iirose.com:8778`（N 为节点编号，由官方下发；`isSocketHttp` 时为 `ws://…:80`）。

## 1. 连接

### 地址

| 客户端 | 地址 | 说明 |
|---|---|---|
| 客户端 | 地址 | 说明 |
|---|---|---|
| 官方网页/Electron | `wss://m{N}.iirose.com:443`（`isSocketHttp` 时为 `ws://…:80`） | 候选节点编号由官方下发 |
| 第三方机器人 | `wss://m{N}.iirose.com:8778` | 具体节点编号以官方为准 |

- 本次未验证 443 / 8778 两个端口的线上等价性或可用性。
- **节点编号不在本文列出**；请以官方下发的节点为准。

### 连接参数

```ts
socket.binaryType = 'arraybuffer';   // 必须：接收/发送都按二进制字节流处理
```

adapter 的 `ctx.http.ws(url)` 底层即标准 WebSocket 客户端，Node 端用 `ws` 库、浏览器端用原生 `WebSocket`。

### 节点选择（adapter 做法）

1. 对可用节点并行 `wss://m{N}.iirose.com:8778` 发连接，测 `open` 事件耗时；
2. 取**延迟最低**的可用节点建立正式连接；
3. 全部失败则按 `5s → 30s → 3min → maxRetryInterval`（默认 30 分钟）递增重试。

## 2. 二进制帧编码（gzip）

WS 收发都可能是二进制，`binaryType='arraybuffer'`：

### 发送（`send.ts`）

```ts
const uintArray = new Uint8Array(Buffer.from(data));
if (uintArray.length > 256) {
  const deflated = zlib.gzipSync(data);
  const out = new Uint8Array(deflated.length + 1);
  out[0] = 1;                  // 首字节 1 = 后续为 gzip
  out.set(deflated, 1);
  socket.send(out);            // ArrayBuffer
} else {
  socket.send(uintArray);      // 原始字节
}
```

- **> 256 字节**才压缩；`<= 256` 直接发原始 `Uint8Array`（不带标记字节）。

### 接收（`message.ts`）

```ts
const array = new Uint8Array(event.data);
let raw;
if (array[0] === 1) {
  raw = zlib.unzipSync(array.slice(1)).toString();  // 首字节 1 → gzip
} else {
  raw = Buffer.from(array).toString('utf8');        // 明文
}
// 解压后按 \0 分割为单条消息（与 transport.md 一致）
const messages = raw.split('\0').filter(m => m.length > 0);
```

> 官方前端用 pako 同逻辑（首字节 `0x01` 判定，见 [transport.md](md/websocket/transport.md?id=frame-codec)），语义一致。一帧可能包含多条消息，用 `\0` 分隔。adapter 的 `message.ts` 未显式 split `\0`（实际由服务端逐帧保证），但为安全起见第三方实现应加上此步骤。

## 3. 登录包（`*` + JSON）

连接建立后，第一条业务消息即登录包：

```ts
socket.send('*' + JSON.stringify(loginObj));
```

### 正式账号字段（adapter `createLoginObj`）

| 字段 | 含义 | 说明 |
|---|---|---|
| `r` | 目标房间 id | 必填 |
| `n` | 用户名 | 必填，不带 `[*...*]` |
| `p` | 认证值 | 按官方登录流程提供（勿传明文） |
| `st` | 在线状态 | `n`/`0`~`9`/`a`~`f`（见状态表） |
| `mo` | 签名/简介 | 可选 |
| `mb` | 客户端标识 | 可空串 |
| `mu` | 流量模式 | **`"01"`**（关系到媒体播放） |
| `lr` | 旧房间 id | 切房后重连认证用，可省略 |
| `rp` | 房间密码 | 密码房才填 |
| `fp` | 指纹 | 由客户端生成，随官方版本变化；以官方客户端行为为准 |

### 认证值（`password.ts`）

登录包中的 `p` 是客户端处理后得到的认证值，**不是明文密码**；具体处理方式随官方版本变化。
本文不展开该细节，请以官方客户端与官方文档为准。

### 在线状态 `st` 取值（`config.ts`）

`n`=无状态、`0`=会话中、`1`=忙碌中、`2`=离开中、`3`=就餐中、`4`=通话中、`5`=移动中、`6`=如厕中、`7`=沐浴中、`8`=睡觉中、`9`=上课中、`a`=作业中、`b`=游戏中、`c`=看剧中、`d`=挂机中、`e`=自闭中、`f`=请撩我。

### 游客模式（额外字段）

游客登录使用另一组字段（由客户端自动构造，本文不展开）：

**结构示意 / 源码片段（非可执行代码）**

```text
{
  r, n,
  i: 头像id, nc: 名字颜色, s: 性别,
  st, mo, uid, li, mb, mu, la, vc,
  fp: 指纹
}
```

### 登录回包判定（`message.ts` 首包）

| 回包前缀 | 含义 |
|---|---|
| `%` | 登录成功（大包，含用户/房间列表） |
| `%*"0` | 名字被占用 |
| `%*"1` | 用户名不存在 |
| `%*"2` | 密码错误 |
| `%*"4` | 请求次数受限（稍后重试） |
| `%*"5` | 房间密码错误 |
| `%*"x` | 账户状态异常 |
| `%*"n0` | 房间无法进入 |

## 4. 心跳与重连

### 心跳差异

| 客户端 | 心跳内容 | 间隔 |
|---|---|---|
| 官方网页端 | 收到服务端 `c` 后回发 `"c"` | 每 2 秒（收到即回） |
| adapter-iirose | 发送**空字符串 `''`** | 每 30 秒 |

- adapter 心跳（`heartbeat.ts`）：`readyState===1` 且状态 ONLINE 时 `send('')`；`readyState===2/3` 或 socket 为空则触发重连。
- **空串不会 gzip**（长度 0 ≤ 256，直接发空字节），服务端识别为保活。

### 重连策略

- 连接失败：换节点（见上节测速/递增重试）。
- 心跳失败（`readyState` 非 OPEN）：触发 `onConnectionLoss` 重连。
- 登录超时（默认 60s 未收到 `%` 首包）：判定登录失败。

## 5. 发送命令速查（业务载荷为明文文本，底层帧自动 gzip 封装）

> 下面列出的命令是**压缩前的明文文本**（即 `IIROSE_WSsend(bot, str)` 的 `str` 参数）。底层 `send.ts` 会自动将 > 256 字节的载荷 gzip 压缩并封装为二进制帧（首字节 `0x01`），详见第 2 节。

### 5.1 消息

| 命令 | 功能 |
|---|---|
| `{"m":"内容","mc":"颜色","i":"12位随机id"}` | 公屏消息 |
| `{"g":"对方uid","m":"内容","mc":"颜色","i":"…"}` | 私聊 |
| `~{"t":"内容","c":"颜色"}` | 全站广播（弹幕） |
| `{0{"m":"…","mc":"…","i":"…"}` | 切歌（`cut` 用此形式） |

- `i`（消息 id）：adapter 用 `Math.random().toString().substring(2,14)`（12 位）。
- 颜色 `mc`：6 位 hex（`rgbaToHex`，忽略 alpha）。默认 `66ccff`。
- 引用：`旧内容 (_hr) 发送者_时间戳秒 (hr_) 新内容`。
- @用户：` [*用户名*] `（两侧空格）；@房间：` [_房间id_] `。
- 图片：`[url#e]`；语音：URL 结尾必须 `.weba`；链接：`\url`。
- Markdown：内容以 `\\\*` + 换行开头。

## 6. 接收报文解析速查

所有回包按**首字符/前缀**路由。字段多用 `>` 分隔（部分用 `"`、`<`）。

### 6.1 大包（用户/房间列表）

- 前缀 `%`，`message.substring(3)` 后按 `\"` 分三段：`parts[0]`=用户+房间、`parts[1]`=当前房间在线用户+历史消息、`parts[2]`=加载信息。
- `parts[0]` 按 `<` 分条，每条按 `>` 分字段。
- **房间**：`fields[0]` 匹配 `/^(?=.*[a-f])([a-f0-9]{10,}_?)+$/`，`fields[1]`=房间名，`fields[5]` 可含 `s://背景地址 简介&&…`。
- **用户**：`fields[0]` 含 `/`（头像路径），字段 `avatar`(0)、用户名(2)、颜色(3)、房间(4)、uid(8)。头像补全为静态资源域名下的 `images/icon/{avatar}.jpg`。
- 解析完成后 adapter 会触发一次 `>#`（股票）和 `>*`（银行）查询。

### 6.2 聊天消息

- **公屏**：前缀为一个双引号字符；普通记录含 11 项：时间 0、头像 1、用户名 2、内容 3、mc 4、nc 5、性别 6、装饰 7、UID 8、等级扩展 9、消息 ID 10。`称号 === "'108"` 是 adapter 的特定标识判断，不能等同于全部等级格式。
- **私聊**：前缀为两个双引号字符，`<` 分条；普通记录 11 个基础字段，自己发送的回显可能追加对方资料，见[官方字段表](md/websocket/messages.md)。adapter 使用的主要字段为：`时间(0) > uid(1) > 用户名(2) > 头像(3) > 内容(4) > mc(5) > 消息id(10)`。
- 引用内容解析：` (_hr) ` 与 ` (hr_) ` 包裹，`发送者_时间戳秒` 结尾。

### 6.3 成员进出

- 前缀 `"`，`parts[3]` 区分：`'1`=加入（末字符 `n`=新加入 / `d`=重连）、`'3`=离开、`'2`=移动（末尾 `3`+目标房间 id）。

### 6.4 经济数据

| 前缀 | 含义 | 字段 |
|---|---|---|
| `>` | 股票 | `substring(1).split('>')[0].split('"')` 长度 5：`总股(0) 总金(1) 单价(2) 我的持股(3) 我的总金(4)` |
| `>$` | 银行 | 按 `"` 拆：`总金(0) 收益(1) 存款(3).split(' ')[0] 余额(4) 利率(5).split(' ')` |
| `` `$ `` | 余额 | `substring(2)` 数字 |

### 6.5 社交回包

| 前缀 | 含义 |
|---|---|
| `$?` | 自身信息回包 |
| `+-` | 用户资料回包（`data.slice(1).split('>')`，字段见 `UserProfileByName.ts`） |
| `@` | 信箱（房间公告 / 关注 / 点赞 / 点踩 / 转账通知） |
| `=` | 广播（`>` 分隔：用户名(0) 内容(1) 颜色(2) 头像(5) 序列(6) 消息id(7)） |
| `~` | 歌单列表 |
| `:-` / `:+` / `:=` / `:*` | 论坛 / 任务 / 朋友圈 / 用户动态 |

以下三个回包前缀以竖线 `|` 开头（单独列出，避免与 Markdown 表格分隔符混淆）：

- `|^`：关注/粉丝列表
- `|_`：打分回包（`分数#倍数`）
- `|$`：转账回执
- `` `# ``：排行榜（前缀为反引号 + `#`）

### 6.6 撤回（`v0`）

- 公屏：`v0#用户ID_消息ID`
- 私聊：`v0*接收方"撤回方_消息ID`

## 7. Node.js 连接骨架：显式校验初始化消息

环境为 Node CommonJS，需调用方提供 `ws` 依赖。下列**函数定义可解析，但不会自动连接**；调用 `openClient` 才会连接并发送登录包。`login` 应按本页字段准备，密码值不得误用明文。节点可用性未在本次修订中验证。

认证失败必须先于初始化判断处理；不能用 `startsWith('%')` 直接进入可发送状态。本地 adapter 已知错误前缀为 `%*"0`、`%*"1`、`%*"2`、`%*"4`、`%*"5`、`%*"x`、`%*"n0`。调用方还须提供验证实际房间载荷结构的 `isInitialRoomData(text)`，不能只验证首字符；未知或不完整消息应返回 false，并最终超时。

```js
const WebSocket = require("ws");
const zlib = require("node:zlib");

function openClient({url, login, isInitialRoomData}) {
  if (typeof isInitialRoomData !== "function") throw new TypeError("需要初始化载荷验证器");
  const connection = new WebSocket(url);
  connection.binaryType = "arraybuffer";
  let phase = "connecting";
  let heartbeat;
  const deadline = setTimeout(() => fail("连接或初始化超时"), 15000);
  const errorPrefixes = ['%*"0', '%*"1', '%*"2', '%*"4', '%*"5', '%*"x', '%*"n0'];

  function cleanup() {
    clearTimeout(deadline);
    clearInterval(heartbeat);
  }
  function fail(reason) {
    if (phase === "closed") return;
    phase = "closed";
    cleanup();
    console.error(reason);
    connection.terminate();
  }
  function sendText(text) {
    const bytes = Buffer.from(text, "utf8");
    connection.send(bytes.length > 256 ?
      Buffer.concat([Buffer.from([1]), zlib.gzipSync(bytes)]) : bytes, {binary: true});
  }
  connection.on("open", () => {
    if (phase === "closed") return;
    phase = "authenticating";
    try {
      sendText("*" + JSON.stringify(login));
    } catch (error) {
      fail("登录包发送失败");
    }
  });
  connection.on("message", data => {
    if (phase === "closed") return;
    try {
      const bytes = Buffer.from(data);
      const text = bytes[0] === 1 ? zlib.unzipSync(bytes.subarray(1)).toString("utf8") : bytes.toString("utf8");
      if (phase !== "authenticating") return;
      if (errorPrefixes.some(prefix => text.startsWith(prefix))) {
        fail("认证失败：收到已知错误前缀");
        return;
      }
      if (text.startsWith('%*"') && !text.startsWith('%*""')) return;
      if (text.startsWith("%") && !text.endsWith("'") && isInitialRoomData(text) === true) {
        phase = "ready";
        clearTimeout(deadline);
        heartbeat = setInterval(() => {
          if (phase === "ready" && connection.readyState === WebSocket.OPEN) {
            try { sendText(""); } catch (error) { fail("心跳发送失败"); }
          }
        }, 30000);
        console.log("房间初始化载荷验证通过；后续命令仍受账号权限约束");
      }
    } catch (error) {
      fail("接收解码或初始化校验失败");
    }
  });
  connection.on("error", () => fail("WebSocket 连接错误"));
  connection.on("close", () => { phase = "closed"; cleanup(); });
  return {connection, getPhase: () => phase, stop: () => fail("客户端已停止")};
}
```

这是生命周期骨架，不包含生产级重连、完整业务路由或服务器权限校验；不会自动回消息。已知错误即使被错误的初始化验证器返回 true，也必须被前置错误分支拒绝。复核至少覆盖错误密码、未知错误、初始化前的其他消息、重复初始化、超时和断线清理。保守分支可能拒绝未知合法变体，需用同版本脱敏载荷扩展，而非放宽成“所有 % 都成功”。
