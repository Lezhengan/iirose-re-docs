> 服务器 → 客户端。源码 `socket.__onmessage(text)` 按首字符分派，正常初始化后该函数移至 `_onmessage`；入参是解码后的字符串。不同消息使用不同分隔符，不能全局统一拆分。

## 聊天消息（`"`）

### 记录边界

`fetchMsg`（L14029）先按双引号字符拆分，首段交给公屏 `getcontents`，第二段交给私聊 `privatechatfunc`。因此以两个双引号字符开头的消息表示首个公屏段为空、后接私聊；不是“两个单引号”。各段内部用 `<` 分记录，每条再用 `>` 分字段，空字段必须保留。

### 公屏

普通记录的字段索引以 L14128、L14185–14186 为准：

| 索引 | 字段 |
|---|---|
| 0 | 时间戳（秒） |
| 1 | 头像值，需按客户端规则补全 |
| 2 | 用户名 |
| 3 | 内容（含转义或特殊内容格式） |
| 4 | 内容色 mc，通常为六位十六进制 |
| 5 | 昵称色 nc |
| 6 | 性别标识 |
| 7 | 装饰字段，可为空 |
| 8 | 用户 UID |
| 9 | 等级/扩展字段，内部还可用单引号分段 |
| 10 | 消息 ID，用于引用/撤回 |

若第 7 项为空，会在性别与 UID **之间**出现连续两个 `>`；不是固定在 UID 之后。游戏/系统记录有额外解释分支，不能把普通字段表当作所有内容格式的解析器。

### 私聊

`privatechatfunc`（L13135–13148）的普通记录含 11 个基础字段：

| 索引 | 字段 |
|---|---|
| 0 | 时间戳 |
| 1 | 发送者 UID |
| 2 | 用户名 |
| 3 | 头像值 |
| 4 | 内容 |
| 5 | 内容色 mc，六位十六进制；异常长度回退为黑色 |
| 6 | 类型，`@` 为匿名分支 |
| 7 | 昵称色 |
| 8 | 性别 |
| 9 | 用户展示背景/大图值 |
| 10 | 消息 ID |

自己发送的回显还读取索引 11 的对方 UID，且可继续带 12–16 的对方资料；不能把普通私聊固定写成 12 项，也不能把额外项一律称为发送者信息。匿名分支会替换部分显示字段；多条记录之间是 `<`，不是字段分隔符 `>`。

### 消息渲染要点

- 引用：`旧内容 (_hr) 发送者_消息id (hr_) 新内容`
- @用户：`[*用户名*]`（两侧空格）
- 匿名：`st:"@"`
- 特殊命令：`/webcam1` `/webcam2`（视频/音频通话，WebRTC，P2P 信令走 `?` 前缀）

## 房间数据（`%`）

这是多种初始化/刷新的共同前缀，不能概括成“百分号后一定是房间 ID”。源码 L13359–13366 按第二字符及后续引号位置处理：非星号分支还携带媒体信息，星号分支可携带离线私信及条件性的银行/股票数据，再交给地图刷新。

同一前缀还有认证错误，例如 `%*"2`。第三方客户端应先处理已知错误，并按实际载荷验证初始化，见[连接骨架](md/websocket/third-party.md)。精确字段需要区分登录态与载荷变体，不能仅凭 `%` 宣告成功或全局按一个模板拆分。

## 切房 / 密码房（`m` 与 `` `~ ``）

移动房间分两步：密码房先发询问包验密码，再发移动包；服务端分别回对应结果码。

**原始内容：**

```text
=^~65cc3d4e2f26f>iirosebot
m6547d48b60b2b
```

**内容解析：**

```text
=^~(目标房间id)>(房间密码)
m(目标房间id)
```

| 回包 | 含义 |
|---|---|
| `` `~1 `` | 密码正确，可继续移动 |
| `` `~0 `` | 密码错误 |
| `m` | 允许移动 |
| `m!5` | 未提供密码 |

> 移动成功后需断开 WS，重新发送登录包把 `r` 改成目标房间，并带上 `lr`（旧房间 id）和 `rp`（目标房间密码，用完即删）。

## whois（`+`）

`+` 响应交给 `whois(payload, Variable.whoisArr)` 构造用户资料视图（L13368）。`Variable.whoisArr` 是本次查询的上下文，不是房间在线列表载荷。

请求入口 `getProfile(value, uidMode)`（L1846）：字符串默认当用户名；按 UID 查询需 `getProfile(uid, 1)`。缓存未命中可发送 `++用户名` / `+&UID`；即使命中在线缓存，仍会按资料上下文选择 `+-` 或 `+@` 等请求，不应承诺无网络。若已有查询上下文未完成，函数会拒绝重入。

`+@` 是特定用户名资料查询变体，不是“按房间名取在线列表”。`f@` 另用于关注店铺。

## 弹幕（`=`）

**原始内容：**

```text
=用户名>内容>mc>nc>性别>头像>时间>uid
```

**内容解析：**

```text
=(用户名)>(内容)>(消息颜色)>(名字颜色)>(性别)>(头像)>(时间)>(uid)
```

## 系统通知（`_`）

按 `e[2]` 二级命令：

| 二级 | 含义 |
|---|---|
| `_0`-`_3` | 余额/奖励（`_3` 送 1 万币） |
| `_p`/`_q` | 私聊相关通知 |
| `_l` | 未读通知 |
| `_!`/`_@`/`_#` | 房内发言/点播限制 |
| `_$` | 被禁言/禁点播（`_$名>时长>原因>类型`） |
| `_%`/`_w` | 黑名单 / 白名单 |
| `_^` | 解除限制 |
| `_r`/`_x` | 其他通知 |
| `__` | console 日志 |

## 房内限制（`.`）

| 二级 | 含义 | 等级映射 |
|---|---|---|
| `.!/` | 发言限制 | 0所有人/1普通+/2带星+/3仅房主/4白名单+/5仅白名单 |
| `.@` | 点播限制 | 同上 |
| `.#` | 发言+点播限制 | — |

## 其他

- `~` 媒体列表、`^` 用户搜索、`:` 动态/任务/论坛、`,` 媒体 seek、`;` 预填输入：均在各自面板处理器中解析
- `Tk`/`Te`/`Ta`：加密币 / 美股 / A股行情，进房时 `%` 数据里带，后续推送更新
